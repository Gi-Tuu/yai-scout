## 2. Fixed findings

| ID | Severity | Finding | Fix | Regression test |
|---|---|---|---|---|
| A1 | **High** | Anchor results were paired to anchors via `zip(anchors, anchor_results)`. If anchor #1 was unreachable and #2 reachable, evidence `anchor_id`/`content_changed` could point to the wrong anchor. | Track explicit `(anchor, result)` pairs in `verify.py`. | `test_unreachable_anchor_does_not_shift_evidence_anchor_ids` |
| A2 | **High** | Revalidation-created candidates with gate decision `reject` were persisted as `pending` (service path), unlike the API path. | Set `accuracy_status=rejected`, `decided_at`, `decided_by=gate`. | `test_candidate_reject_status_and_dedupe` |
| A3 | **High** | `POST /freshness/anchors` accepted `temporal_sensitivity` but did not persist it. TTL always used `None` → always due. | Pass `temporal_sensitivity` into `Anchor`. | anchor API test asserts value |
| A4 | **High** | Revalidation never updated a check timestamp, so every due anchor stayed due forever and every cron run re-fetched/re-candidated. | Added `Anchor.last_checked_at`; TTL uses max(verified, checked); revalidation updates it. | `test_revalidate_records_change_without_overwriting` asserts no longer due |
| A5 | **High** | Primary revalidation observation used the full URL as `independent_group`, while discovery used a domain. | A6 | Medium | Candidate apply wrote new anchor and marked old superseded in two transactions; a crash could leave two active anchors. | Added atomic `store.save_anchor_replacement()`. | existing candidate/rollback tests |
| A7 | Medium | Candidate apply logic was duplicated in API create/approve and service; selection rules diverged (latest vs highest-tier). | API now calls the shared `apply_candidate()` service. | candidate approval tests |

| A9 | Medium | Live anchor fetch used httpx defaults, so `HTTP(S)_PROXY` could bypass pinned-IP SSRF protection. | `trust_env=False` on the live client. | full suite |
| A10 | Low | Anchor/candidate indexes were missing; one index was created before its table (caught during audit). | Indexes added after table creation. | store init tests |

## 4. Data-model assessment

- **Anchor**: append-only, `supersedes`/`superseded_by`, statuses `active/superseded/unreachable/rolled_back`; `last_checked_at` now separates “verified” from “checked”.
- **AnchorObservation**: one row per check, stores URL/tier/group/value/hash/time; immutable payload.
- **AnchorCandidate**: gate decision + evidence + status; `pending → approved/rejected/auto_applied`, plus `no_change`.
- **Snapshot / DetectorReport / BenchSession**: manifest/result hashing and immutability are consistent.
- Main structural gap: candidate evidence is untyped; rollback does not cascade to candidate state.

## 5. Robustness / failure behavior

- Tavily failure → `INSUFFICIENT`, no fake evidence.
- LLM failure → rule fallback (claim extraction/relation).
- Bifrost unavailable → direct fallback or rule mode; no false “Bifrost” claim.
- Live anchor fetch default off; HTTPS-only, exact allowlist, no redirects, public-IP + pinned IP, Host/SNI, `trust_env=False`.
- Public cost guard now covers detector, benchmark, and anchor creation.
- Revalidation is bounded by discovery TTL/cache and daily budget.
