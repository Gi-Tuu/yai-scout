# P0 Freshness Correctness — 2026-11-02

Baseline: `c2293c1` + pending working tree. Scope: only confirmed issues in
`freshness.py`, `verify.py`, `temporal.py`.

## Fixed

### 1. Old authoritative support no longer means FRESH

Before: any T1/T2 `supports` evidence produced `FRESH`, even if published years
before a SENSITIVE claim.

Now:
- STABLE claims still accept old support;
- SENSITIVE / VOLATILE claims require at least one authoritative support whose
  `published_at`/`updated_at` is inside the claim window;
- expired or undated authoritative support → `INSUFFICIENT`, not `FRESH`.

Tests: `test_old_authoritative_support_is_not_fresh`,
`test_undated_authoritative_support_is_not_fresh`.

### 2. Numeric relation no longer uses arbitrary number overlap

Before: `any(claim_number in evidence_numbers)` → `supports`.

Now:
- DATE claims with only a year → `mentions` (year overlap is not support);
- VERSION claims compare normalized version tokens (`v0.24.0` == `0.24.0`);
- currency codes/symbols are compared (`USD` vs `EUR` → contradict);
- credits vs money → contradict;
- periods (`/month` vs `/year`) → contradict;
- all claim numbers must be present, excluding year tokens for non-date claims;
- unsupported/ambiguous → `mentions`.

Tests: `tests/test_relation_rules.py` (9 cases).

### 3. Year regex

Before: `(19|20)\d{2}\s*年` made `findall()` return `"19"`/`"20"`.

Now: a non-capturing prefix plus full-year capture; future years no longer
classified as historical STABLE facts.

Tests: `tests/test_temporal.py` (1998 / 2026 / 2099).

## Fixed (as_of / timestamp)

### 4. Live vs replay as_of

- Live mode without `as_of` uses the current UTC date;
- Replay mode requires an explicit `as_of` and returns 400 otherwise;
- invalid `as_of` returns 400 instead of silently falling back;
- the same effective as_of is passed to the detector/replay/live paths;
- `build_query` uses the requested year, not a hard-coded 2026.

Tests: `tests/test_as_of.py`.

### 5. Publication vs retrieval time

- `SearchResult` carries `retrieved_at` separately from `published_date`;
- live anchor fetch sets `published_date=None` and `retrieved_at=fetch time`;
- replay sets `retrieved_at=snapshot.fetched_at`;
- evidence keeps `retrieved_at` distinct from `published_at`;
- scoring still uses published/updated time only, so retrieval time cannot make
  an old page look fresh.

Tests: `tests/test_anchor_live.py`.

## Fixed in Stage B (2026-11-02)

### 6. Temporal eligibility (P0-1)

- Future evidence is excluded in live and replay.
- Old contradictions no longer cause STALE; only current contradictions do.
- Old support + new contradiction -> STALE (not CONFLICTED).
- Old contradiction + new support -> FRESH.
- Unknown-date contradictions cannot cause STALE.
- STABLE may use expired support; expired contradictions are excluded.
- Tests: `test_freshness.py` (22 cases).

### 7. LLM attribution (P0-2)

- Aggregate LLM relation is stored in `FreshnessVerdict.claim_assessment`.
- No longer overwrites `evidence[0]`.
- Tests: `test_llm_attribution.py`.

### 8. Version semantics (P0-3)

- Distinguishes latest/current release from previous/historical versions.
- Historical version in a latest+previous page no longer supports a current claim.
- Ambiguous multiple unmarked versions -> mentions.
- Tests: `test_version_relation.py`.

### 9. Gate time guard (P0-4)

- Missing/invalid anchor time -> REVIEW.
- Missing/invalid/future observation time with a new value -> REVIEW.
- Only known observations at/after anchor can be newer.
- Tests: `test_accuracy_gate.py`.

### 10. Coverage and receipt MVP (P1)

- `DetectorReport` now exposes `coverage`, `abstention_rate`, `scored_claims`, `unknown_claims`.
- `/freshness/reports/{id}/receipt` returns versioned evidence receipts.
- Receipt records evidence kind, content hash, published/retrieved times, limitations.
- Tests: `test_coverage.py`, `test_receipt.py`.
